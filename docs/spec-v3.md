# TZG 商品上架跟進 — 規格 v3（草案，9/25 第三版）

> 取代 v2.1 的流程與身分設定。沒寫到的部分沿用 v2.1，包括：裝置綁定登入、時間歸屬、延誤分析、賽道全覽、泡泡風格。

## 1. 身分與人數

| 身分 | 人數 | 負責 |
|---|---|---|
| 行銷 | 2 | 開單（提供選品照片），最後投放前檢查 |
| 美編 | 2 | 首圖去背 |
| 上架人員 | 2 | Shopline 上架 |
| 設計師 | 1 | 優化線上頁面 |
| 管理員 | 1 | 設定、改派、手動推到下一關 |

取消「選品」（併入行銷）和「審查人」。

## 2. 流程

| 步 | 負責 | 做什麼 | 完成條件 |
|---|---|---|---|
| 1 開單 | 行銷 | 從同步進來的商品中開單，上傳選品照片 | 至少 1 張照片 |
| 2 去背 | 美編 | 做首圖去背 | 上傳去背圖 |
| 3 上架 | 上架人員 | 用照片和去背圖上 Shopline | 貼上 Shopline 網址 |
| 4 優化 | 設計師 | 直接改 Shopline 線上頁面 | 寫下「改了什麼」 |
| 5 行銷檢查 | 開單的同一位行銷 | 投放前最後檢查 | 按「檢查通過」 |
| ✓ 已完成 | — | 移到「已完成」區 | — |

**檢查與退回**
- 不設審查人。每一關接手的人照常做自己的事，發現上一步有問題就按「退回上一步」，並寫出哪裡有問題。留言必填。
- **行銷檢查可以退回任何一步**。被退回的人改好之後，**直接交回行銷**，不再經過中間的關卡。
- 退件次數算在被退回那一步的負責人身上。
- 正確性由頭尾這位行銷負責，中間的人不負最後把關的責任。

**認領，不指派**
- **美編**：自己登入，看到就按「我來做」認領，不指定、也不分台灣或大陸。
- **上架人員**：誰看到誰就按「我來做」認領。
- **設計師**：只有 1 人，自動接手。
- 還沒人認領的件，會出現在那個身分所有人的待辦裡。認領後就只出現在認領人那裡。
- 計時從「輪到這一關」開始算，沒人認領的等待時間也算在這一關，所以全覽看得出來是哪一關沒人接。
- 管理員可以改派，也可以手動推到下一關。

**插隊**
- 在系統裡手動設定，不從試算表同步。
- 設定時只選完成日期，不選時間，算到那天下班為止。最早只能選明天，不能選當天。
- 插隊的件排在最前面，剩 2 個上班日內自動變急件。

## 3. 試算表同步

- **來源**：「廣告數據表」的「銷售型-投廣素材」分頁，由行銷維護。
- **欄位**：第 5 列是標題，資料從第 6 列開始。
  - A 欄 狀態
  - C 欄 商品／活動 → 商品名稱
  - D 欄 商品連結（Shopline 商品頁）→ 系統裡的商品名稱會自動連到這個網址
  - 其他欄（參數連結、影片、商品頁負責人等）不同步
- **方向**：單向，試算表 → 系統，系統不會回寫試算表。
- **同步內容**：
  - 商品名稱，連同名稱儲存格上的商品連結
  - 狀態（A～D）；插隊在系統裡手動設定，不從試算表來
- **全部匯入、全部重跑**：每一列都建成商品卡，從「開單」開始走流程，包括 A 投放中、C 可投放的商品。
- **排序**：插隊（依截止日先後）> A 投放中 > B 優先製作 > C 可投放 > D 待製作。全覽可以依狀態篩選。
- **之後每次同步**：
  - 已經有的商品只更新狀態和連結，流程進度不會被重置。
  - 試算表刪掉的商品，一律標成「已下架」，保留紀錄、不刪除。
- **首圖縮圖**：系統打開 D 欄的 Shopline 商品頁，讀取頁面標註的首圖（og:image），存成縮圖放進系統；首圖換了，下次按同步會跟著更新。
- **怎麼同步（手動）**：
  - 行銷在 Google 試算表把「銷售型-投廣素材」這一頁「發布到網路（CSV 格式）」，把產生的網址貼到系統的設定頁（只要做一次）。
  - 系統裡有兩顆按鈕：「同步試算表」和「同步首圖」，按了才會跑，不會每天自動跑。
  - 只有**設計師**和**管理員**看得到、按得到這兩顆按鈕。
  - 不需要提供任何 Google 帳號或金鑰。發布出去的網址只有拿到網址的人看得到內容。

## 4. 成效怎麼看（取消標準時間）

- 各步**不設標準時間**，全覽也不再顯示「領先／落後標準」。
- 全覽每一步、每一列右側改成**跟團隊平均比**：這件在這一步花的上班時數，對比同一步所有商品的歷史平均，顯示「比平均快 X 小時」或「比平均慢 X 小時」。
- 慢超過平均 1.5 倍標成琥珀色，超過 2 倍標成紅色，並寫出「偏慢」文字，不只靠顏色。
- 沒人認領的等待時間算在那一步，所以看得出來是哪一關沒人接。
- 延誤分析頁：每個人每一步的平均時數、跟團隊平均的差距、被退件次數和原因。
- 插隊件另外看：離截止日剩 2 個上班日內標成急件，錯過截止日的件數列在分析頁。

## 5. 細節

| 項目 | 做法 |
|---|---|
| 狀態對應 | 投放中＝A、優先製作＝B、可投放＝C、待製作＝D；不認得的狀態排最後 |
| 開單 | 同步進來的商品先放在「待開單」，任何一位行銷都可以按「我來開單」認領。認領的人就是最後做行銷檢查的人 |
| 手動開單 | 試算表以外的商品，行銷也可以在系統手動新增（填名稱和商品連結） |
| 插隊截止 | 只選日期，算到當天下班；不能選當天 |
| 同步 | 手動按鈕，只有設計師和管理員能按 |
| 首圖縮圖 | 手動按「同步首圖」更新；顯示在全覽和待辦的商品名稱左邊 |
| 成員 | 行銷 2 位、美編 2 位、上架 2 位、設計師 1 位、管理員 1 位。線上多出來的「選品 1–3」「審查 1–3」「行銷 3」「美編 3」「上架 3」刪除（都還沒有人使用） |
| 已下架 | 從全覽的進行中移出，放到「已下架」篩選裡；如果試算表又加回來，自動恢復 |
| 舊資料 | 線上目前沒有商品，直接換成新流程，不做資料轉換 |
